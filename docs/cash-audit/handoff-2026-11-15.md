## 3. What was changed, and why
Review of GPT Work's code found and fixed:
| Issue | Fix |
|---|---|
| The reconcile function reset every event to pending then re-matched, so a trigger would write 2 spurious audit rows per matched event every 5 minutes | Snapshot before, write only **net-change** audit rows (`cash.skip_audit` setting, temp table) |
| Service-role check read only `request.jwt.claim.role`, which newer PostgREST may not set | Falls back to `request.jwt.claims` JSON |
| Manual review left `changed_by` null (service-role caller has no `auth.uid()`) | Attributed to the owner passed in |
| 7 PM report only ran in the 19:05 to 19:59 window | Catches up any time after 19:05; tick accepts `force_report` and `date` (cron key only); a forced rerun **updates the same card** (no duplicate notification) |
| POS sync every 10 min, 8:00 to 19:59 = 72 agent runs a day | Every 15 min, 9:00 to 18:45 = about 40 runs a day (`*/15 9-18 * * *`) |
| `setup()` saved a newly created schedule only at the end, so a later failure could orphan it and a retry would create a duplicate | Saved immediately after each create (gateway v15) |

UI additions: per-schedule on/off switches, a **Create** button on any schedule that does not exist yet (logs proved Update had never been pressed because it lives in a collapsed box), readable "Every 15 min · 9am–6:45pm" label (the old formatter showed "Daily · 12pm").

## 8. Rules and gotchas for whoever works on this next
- `deploy_edge_function` requires **all** gateway files every time: `index.ts, cma.ts, stockwise_def.ts, cash.ts, cash_core.ts, cash_store.ts, cash_match.ts, cash_phase2.ts`. After every deploy fetch the function and diff against the repo.
- `stockwise_def.ts` is generated: edit `agents/stockwise/*` then run `node agents/stockwise/build.mjs`. Deploying it does **not** change the live agent; the in-app Setup/Create does.
- The sandbox cannot reach any `*.supabase.co` host. Production work went through the Supabase connector; the cron key was never read, the database called the tick itself with `net.http_post`.
- Rollback: redeploy the eight files from commit `2b6af37` (v12). Data backup is the `cash_backup_20261115` schema.
- Do not touch the live Jetson uploader, retention system or Stockwise POS.
